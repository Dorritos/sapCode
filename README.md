# САП КОД — практическое задание AI-разработчика

**Задача:** устранить ошибки в обработчике входящих заявок.

**Рекомендуемый лимит:** 60–90 минут. **AI разрешён:** ChatGPT, Codex, Claude Code, Cursor и др. Можно использовать официальную документацию. Выполняйте самостоятельно; не передавайте задание другому человеку.

Это **учебный проект**, не коммерческая работа. Все данные синтетические. Знание SAP CODE Engineering OS не требуется.

## Ситуация

В систему поступают сообщения с запросами клиентов. Одно и то же сообщение может приходить несколько раз из-за повторной доставки. Сейчас обработчик ошибочно сохраняет дубликаты и повторно создаёт уведомления. В нём есть и другие ошибки обработки входных данных.

В `app.py` находится функция:

```python
process_event(event: dict, db_path: str) -> dict
```

Она использует SQLite (входит в стандартную библиотеку Python). При вызове открывает базу данных по `db_path` и сохраняет заявки в таблицу `leads`, а события для будущей отправки уведомлений — в таблицу `notifications`.

## Что требуется исправить

1. **Уникальность заявки:** одна заявка определяется парой **(`source`, `external_id`)**, а не одним `external_id`. Если событие пришло повторно, не добавляйте новую заявку и новое уведомление. Верните существующий `id`.
2. **Новая заявка:** если такой пары ещё нет, сохраните заявку и создайте **одно** уведомление в таблице `notifications`.
3. **Проверка данных:** поля `source`, `external_id`, `customer`, `message` обязательны, должны быть строками и не должны быть пустыми после удаления пробелов по краям. Некорректное событие не должно создавать заявку или уведомление и не должно приводить к необработанному исключению.
4. **Пробелы:** перед сохранением и сравнением удаляйте пробелы по краям каждого из четырёх полей. Регистр букв сохраняйте; `Telegram` и `telegram` считаются разными источниками.
5. **Повтор с изменённым текстом:** при повторе той же пары (`source`, `external_id`) первоначальные `customer` и `message` должны оставаться без изменений.
6. **Сохранность:** повторное создание подключения к той же базе не должно сбрасывать данные.
7. **Тесты:** существующие тесты должны проходить. Добавьте минимум **два своих теста** на важные сценарии, которые считаете недостаточно покрытыми.

Не нужно создавать веб-интерфейс, Telegram-бота, внешний API, Docker-конфигурацию или новую архитектуру. Не используйте сторонние библиотеки. Можно менять `app.py`, добавлять тесты, индексы, ограничения и небольшие вспомогательные функции; сохраните публичный интерфейс функции и имена существующих таблиц и столбцов.

## Формат ответа функции

**Новая заявка:**

```python
{"status": "created", "id": 1}
```

**Повтор:**

```python
{"status": "duplicate", "id": 1}
```

**Некорректная заявка:**

```python
{"status": "invalid", "reason": "Непустое понятное объяснение"}
```

Для первых двух вариантов `id` должен быть целым положительным числом. При повторе должен возвращаться тот же `id`, что и при первичной обработке.

## Как запустить

Нужен **Python 3.10+**. Установка пакетов не требуется.

```bash
python -m unittest discover -s tests -v
```

На исходной версии часть тестов **специально не проходит**. Ваша задача — добиться успешного выполнения и добавить минимум два теста. Не меняйте проверки существующих тестов ради «зелёного» результата.

3. Подтверждение работы с Git: ссылка на коммит или вывод `git log -2 --oneline`. Рекомендуется сделать отдельный коммит с решением. Если Git не удалось использовать — честно укажите это в отчёте.

**Не присылайте** `.sqlite3` с реальными данными, секреты, токены, пароли, лишние ZIP с окружениями и сторонние зависимости.
